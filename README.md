# DB Workspace Pro

Настольное приложение для Windows (Python + PySide6) для работы с Microsoft SQL Server:
подключения, обозреватель объектов, SQL-редактор, отчёты Word, конвертер, автоматизация и т. д.

> **Статус: все 7 этапов реализованы (версия 0.7.0).** Каждый раздел меню — рабочая страница; заглушек нет.
> Подробные руководства: [docs/user_guide.md](docs/user_guide.md) (пользователь),
> [docs/admin_guide.md](docs/admin_guide.md) (установка, права SQL Server, безопасность, сборка),
> [docs/CHANGELOG.md](docs/CHANGELOG.md). Они же открываются в программе: «Справка» (F1).

## Возможности

* Профили подключения к SQL Server: локальный/удалённый сервер, именованный экземпляр, порт, база по умолчанию,
  аутентификация Windows и SQL Server, шифрование (`yes` / `no` / `strict`), проверка сертификата
  (по умолчанию **включена**; отключение — только осознанным флажком с предупреждением), тайм-ауты.
* Пароли хранятся **только** в Windows Credential Manager (через `keyring`). Если системное хранилище недоступно —
  пароль живёт лишь в памяти процесса. В SQLite, JSON и журналы пароли не попадают (проверено тестами).
* Проверка соединения на отдельном временном подключении, подключение/отключение, статус, переподключение
  после потери связи (автоповтор — только для безопасных операций чтения).
* Обозреватель объектов (ленивая загрузка в фоне): серверы → базы → таблицы, представления, процедуры, функции,
  триггеры → столбцы, первичные/внешние ключи, индексы; свойства, определение (T-SQL) модулей,
  копирование имён, фильтр, несколько серверов одновременно.
* Главная панель, светлая/тёмная тема, боковая навигация, история задач, настройки, диагностика окружения.
* Фоновые задачи: очередь, лимит параллельности, отмена, прогресс, журнал; единый механизм для всего приложения.
* Журнал в `%APPDATA%\DBWorkspacePro\logs` с автоматическим маскированием паролей/токенов.

### SQL-редактор (этап 2)

* Вкладки скриптов; **у каждой вкладки своё соединение** (как окна запросов в SSMS), выбор подключения и базы (`USE`).
* Подсветка T-SQL (в т. ч. многострочные строки и вложенные комментарии), номера строк, автоотступ, Tab/Shift+Tab.
* Выполнение выделенного фрагмента или всего скрипта (F5 / Ctrl+Enter) **в фоне**; разделитель `GO`; несколько
  наборов результатов; сообщения сервера (`PRINT`) и число затронутых строк; время выполнения; отмена запроса.
* Тайм-аут на вкладку; потоковое чтение порциями, предел строк предпросмотра (по умолчанию 1000, настраивается).
* Подсветка ошибок: локально (незакрытые строки, комментарии, скобки) и по тексту сообщения сервера
  (место определяется **приблизительно** — ODBC не сообщает позицию ошибки).
* Автодополнение (Ctrl+Space и при вводе): ключевые слова, функции, объекты базы, столбцы таблиц запроса и
  `псевдоним.` — по кэшу схемы, загружаемому в фоне. Работает «по возможности»: учитываются таблицы всего пакета.
* История запросов (поиск, повторное открытие), избранное, открытие/сохранение `.sql` (кодировка определяется,
  скрипт **никогда не выполняется автоматически**).
* Копирование ячеек (с заголовками) и экспорт в **CSV, Excel, JSON**: показанные строки либо **все строки запроса
  потоком** (повторное выполнение на отдельном соединении — только для запросов на чтение).
* Excel: разбиение на листы при превышении лимита 1 048 576 строк, защита от формул, длинные `bigint` как текст.

**Безопасность редактора.** По умолчанию включён режим «только чтение»: INSERT/UPDATE/DELETE/DDL/EXEC и т. п.
блокируются **в ядре сессии**, а не только в интерфейсе. Для изменений нужно (1) отметить «Разрешить изменения» и
(2) подтвердить выполнение; для DELETE, DROP, TRUNCATE, UPDATE без WHERE, динамического SQL и подобного — ввести слово
`ВЫПОЛНИТЬ`. Есть режим «Транзакция» с кнопками «Зафиксировать» / «Откатить»; закрытие вкладки с открытой
транзакцией откатывает её после подтверждения. Анализ команд консервативный (лучше лишний вопрос) и не заменяет
права доступа: для отчётов используйте учётную запись только на чтение.

Ограничения: `GO n` с повтором не поддерживается; при ошибке пакета последующие пакеты не запускаются; динамический
SQL не анализируется; план выполнения, отладчик и IntelliSense уровня SSMS **не реализованы**; отмена запроса
зависит от драйвера и сервера.

### Отчёты и шаблоны (этап 3)

* **Код запроса и результат в отчёте:** сохранённые запросы из «Избранного» доступны как шаблоны отчёта; флажок
  «код запросов и их результаты в конце отчёта»; блок «Код запроса и результат» в конструкторе.

* **Генератор отчётов** («Отчёты Word»): подключение → база → шаблон → параметры → форматы → папка. Предпросмотр
  структуры отчёта, ход выполнения с отменой, список готовых файлов (двойной щелчок — открыть), недавние отчёты на
  главной. Если один формат не получился, уже готовые остальные **сохраняются**.
* **Форматы:** Word `.docx`, PDF (через LibreOffice), Excel `.xlsx`, CSV, HTML, Markdown — все из одного описания отчёта.
* **Word:** титульная страница, оглавление (поле Word), разделы, таблицы (повтор шапки на новой странице, запрет
  разрыва строк, чередование цветов, выравнивание чисел, итоги, выделение пустых значений, автоширина, **автоматический
  переход широких таблиц на альбомную страницу**), статистика, диаграммы, выводы, примечания о параметрах формирования,
  колонтитулы с «Страница X из Y». Можно использовать **свой шаблон Word** (`.docx`/`.dotx`) с переменными `{{…}}`.
* **Шесть стилей:** Деловой, Академический (таблицы «тремя линиями»), Минималистичный, Аналитический, Технический,
  Финансовый; шрифт, размер, поля, ориентация и цвет акцента можно переопределить.
* **Источники данных:** SQL-запрос с параметрами `:имя`, таблица/представление (столбцы, фильтры, группировка,
  агрегаты, сортировка), хранимая процедура (только с вашим подтверждением, что она читает данные).
* **Статистика и диаграммы только там, где они уместны:** суммы и средние не считаются для текста, дат и
  идентификаторов; столбчатые, линейные и круговые диаграммы строятся лишь для подходящих данных, иначе в отчёте
  остаётся пояснение, почему диаграммы нет. «Выводы» содержат только факты, вычисленные из полученных строк.
* **Большие данные:** лимит строк на таблицу, разбиение на разделы по значению столбца, **деление отчёта на части**
  (отдельные файлы). Измерено на этой машине: DOCX из 20 000 строк — около 2 с, XLSX — около 3 с.
* **Конструктор шаблонов:** общие настройки, параметры, источники (с проверкой по первым 20 строкам), блоки
  (заголовок, текст, таблица, статистика, диаграмма, выводы, примечания, разрыв страницы; перестановка), импорт и
  экспорт JSON. Встроенные примеры лежат в `examples/report_templates/` и работают на любой базе (системные каталоги).

**Безопасность отчётов.** Запросы источников проходят ту же проверку, что и SQL-редактор: допускается только чтение и
один пакет; значения параметров передаются параметрами `?`, имена объектов экранируются; существующие файлы по
умолчанию не затираются; текст из данных очищается от символов, ломающих XML; значения-формулы в CSV/Excel
обезвреживаются; HTML и Markdown экранируются.

**Ограничения отчётов.** Номера страниц в оглавлении Word появляются после обновления поля в Word (при открытии нажмите
«Обновить поле»); в PDF оглавление без номеров страниц. Вид PDF зависит от шрифтов, установленных там, где работает
LibreOffice. Источник читается только по первому набору результатов. Сортировка применяется к уже полученным строкам.
Страницы в HTML/Markdown не нумеруются. Файлы Word проверены `python-docx` и LibreOffice, но не самим Microsoft Word.

### Конвертер файлов (этап 4)

* **Очередь файлов:** перетаскивание файлов и папок в окно, «Добавить файлы/папку» (с подпапками, структура папок
  сохраняется в результате), выбор формата результата, папка результата или «рядом с исходным», политика имён
  (добавить номер / перезаписать / пропустить). Пакет выполняется **в фоне** с прогрессом и **отменой**; по каждому
  файлу видны состояние, результат и замечания; журнал и вкладка «История».
* **Таблица совместимости** (кнопка в конвертере) показывает все пары форматов, способ выполнения и что при этом
  теряется. Программа **не обещает «любой во любой»**: пара либо поддерживается, либо объясняется причина отказа.
* **100 поддерживаемых пар** между форматами DOCX, DOC, ODT, RTF, HTML, Markdown, TXT, SQL, PDF (только как результат),
  XLSX, XLS, CSV, TSV, JSON:

| Способ | Что это |
|---|---|
| встроенный (без внешних программ) | DOCX/Markdown/HTML/TXT ↔ друг в друга (кроме записи в PDF); таблицы XLSX/CSV/TSV/JSON ↔ друг в друга; SQL ↔ TXT; **извлечение таблиц** из DOCX/HTML/Markdown в XLSX/CSV/TSV/JSON |
| LibreOffice | DOCX/DOC/ODT/RTF/HTML/TXT → PDF/DOCX/DOC/ODT/RTF/TXT/HTML; XLSX/XLS → PDF, XLS ↔ XLSX |
| цепочка из двух шагов | Markdown → PDF/DOC/ODT/RTF; DOC/ODT/RTF → Markdown; CSV/TSV/JSON → PDF/XLS; XLS → CSV/TSV/JSON; **любой → DOC** (через ODT) |

* **Не поддерживается:** PDF как исходный формат (без OCR и потерь содержимое не вернуть), таблицы → текстовые
  документы, SQL → документы, и другие пары без надёжного маршрута.
* **Контроль качества каждого результата:** файл создан, не пуст и открывается доступными средствами (python-docx,
  openpyxl, структура ZIP/OLE, сигнатура и конец PDF, разбор JSON и HTML, UTF-8 для текста); по итогам пакета
  сверяется, что число результатов совпадает с числом файлов, а у каждой успешной операции есть файл. Повреждённый
  результат считается ошибкой и не сохраняется. О потерях оформления сообщается заранее и в замечаниях.
* **Безопасность и надёжность:** исходные файлы никогда не изменяются и не перезаписываются (даже при политике
  «перезаписывать»); результат пишется во временную папку и переносится атомарно, при сбое частичные файлы
  убираются; проверка свободного места; отмена завершает процесс LibreOffice; ссылки в Markdown/HTML очищаются от
  `javascript:`; HTML экранируется; формулы в CSV/Excel обезвреживаются (настройка); временные файлы удаляются.
* **Особенности:** кодировки определяются автоматически (UTF-8/BOM/UTF-16, иначе предполагается cp1251 — с
  предупреждением); разделитель CSV определяется по содержимому; первая строка таблицы считается заголовком;
  числа и ISO-даты из CSV распознаются при записи в Excel (значения с ведущими нулями остаются текстом); у книг Excel
  с несколькими листами для CSV/TSV/JSON создаётся файл на лист; формулы без сохранённых значений (файл создан не в
  Excel) переносятся как пустые — об этом предупреждается; «переименованные» файлы (.doc, который на деле .docx)
  распознаются.
* **Скорость (измерено на этой машине):** CSV 12,6 МБ / 200 000 строк → TSV 1,3 с, JSON 1,8 с, XLSX 23 с (память
  растёт слабо — файл читается потоком); Markdown 141 КБ → DOCX 7 с, → HTML 0,4 с. Каждое преобразование через
  LibreOffice занимает 1–3 с (запуск программы), поэтому для пакетов можно включить 2–3 потока в «Настройках».

**Ограничения конвертера.** Встроенные преобразования Markdown/HTML/DOCX сохраняют заголовки, абзацы, списки,
таблицы, полужирный/курсив/код и ссылки; изображения, колонтитулы, сноски, CSS и сложное оформление не
переносятся (разбор Markdown — подмножество CommonMark: без вложенных блоков внутри списков и встроенного HTML).
Для DOC, ODT, RTF, XLS и PDF нужен LibreOffice. Вид PDF зависит от установленных шрифтов. Большие JSON читаются целиком
в память (предел 200 МБ). Макросы и встроенные объекты документов не обрабатываются.

### Автоматизация и мониторинг (этап 5)

* **Планировщик задач** (собственный, без внешних библиотек): однократно, через интервал, ежедневно, по дням недели,
  ежемесячно (31-е → последний день месяца), после подключения к серверу (только для задач чтения). Задачи и история
  хранятся в базе приложения и переживают перезапуск. Двойной запуск одной задачи невозможен; долгий запуск не
  «задваивается» расписанием.
* **Честно о закрытой программе:** встроенный планировщик работает, только пока программа открыта. Пропущенные запуски
  не выполняются задним числом (если не включено «выполнить при следующем запуске») и отмечаются в истории и
  уведомлениях. Для запуска при закрытой программе есть **задание Планировщика Windows**: программа формирует XML
  (не зависит от языка системы) и команду `schtasks`, а задача выполняется командой `main.py --run-task ID` без окна
  (от имени пользователя, когда он вошёл в систему; для входа по паролю SQL Server пароль должен быть сохранён).
* **Виды задач:** формирование отчёта (со снимком данных и **сравнением с прошлым запуском**: новые, удалённые,
  изменённые записи по выбранному ключу и изменения сумм; при неуникальном ключе сравнение честно отклоняется),
  экспорт таблиц в CSV/XLSX/JSON, резервное копирование, проверка доступности сервера (с уведомлением о сбое и о
  восстановлении), сбор размеров таблиц, запуск SQL-сценария. Уведомления: только об ошибках, всегда или никогда.
* **Резервное копирование:** полная копия `COPY_ONLY` (не ломает цепочку копий администратора), `CHECKSUM`,
  проверка `RESTORE VERIFYONLY`, история из `msdb`, понятные подсказки при типичных ошибках (нет прав на папку, нет
  папки, сжатие в Express). Путь — **на сервере**; если папка видна с компьютера, проверяется и сам файл.
  **Очистка** старых копий — только по явной настройке с согласием, только файлов этой программы
  (`База_ГГГГММДД_ччммсс.bak`), самые новые копии не удаляются никогда, после неудачной копии очистка не запускается.
  **Восстановление** — отдельная защищённая операция: только в **новую** базу (существующие не затрагиваются), с
  повторным вводом имени; для замены существующей базы программа выдаёт инструкцию и скрипт для ручного выполнения.
* **SQL-сценарии:** хранение, параметры `:имя`, выбор подключения и базы, тайм-аут, сохранение результата в CSV,
  журнал запусков. Изменяющий сценарий запускается только если разрешены изменения **и подтверждён именно этот текст
  SQL** (после правки подтверждение снимается); по умолчанию — в транзакции с откатом при ошибке. Импортированные из
  файлов сценарии сами не запускаются.
* **Мониторинг:** доступность и время отклика, размеры баз, число таблиц, крупнейшие таблицы (строки и объём),
  активные запросы и блокировки (только при праве VIEW SERVER STATE — иначе картина была бы неполной, и программа
  об этом пишет), история отклика (график), ошибки приложения и длительность запросов редактора, время обновления.
  Показатель без данных или без прав не выводится — вместо него заметка.
* **Уведомления** — в программе (вкладка «Уведомления» и счётчик в строке состояния). Данные никуда не отправляются.

**Ограничения этапа 5.** Резервное копирование и восстановление проверены на имитации сервера, а не на реальном
SQL Server (есть отдельные интеграционные тесты по явному включению). Права на `BACKUP`/`RESTORE`/`msdb`/DMV зависят
от настроек сервера. Время расписания — локальное время компьютера (переходы на летнее время не учитываются
особо). Задание Windows не создаётся для «после подключения» и для 29/30-го числа (их нельзя выразить точно).
Уведомления по электронной почте не отправляются.

### Сравнение баз и документация (этап 6)

* **Сравнение структуры** двух баз (в том числе на разных серверах) или выбранных таблиц: таблицы, столбцы (тип,
  NULL, IDENTITY, вычисляемые, значения по умолчанию, сортировка), первичные и внешние ключи, индексы, представления,
  процедуры, функции, триггеры. Ограничения и индексы сопоставляются **по сути**, а не по имени: имена, сгенерированные
  сервером (`PK__Orders__3214EC07…`), в разных базах всегда различаются и не считаются различием (это можно
  включить). Определения модулей сравниваются без учёта пробелов (настраивается); если определение недоступно (нет
  права VIEW DEFINITION), объект помечается «сравнить нельзя», а не «одинаковый».
* **Сравнение данных** двух таблиц по ключу (в том числе составному; текстовые ключи — без учёта регистра, как в
  SQL Server по умолчанию): новые, удалённые и изменённые записи, суммы числовых столбцов. Неуникальный ключ и таблица
  больше лимита — честный отказ с объяснением, а не «сравнение» части данных.
* **Отчёты о сравнении** — Word, Excel (и HTML).
* **Скрипт синхронизации** (структура и данные) только формируется и показывается: предупреждения, что сделать
  вручную, оценка риска. Удаления (`DROP`, `DELETE`) по умолчанию закомментированы. Рискованные изменения подписаны
  прямо в скрипте; новый столбец `NOT NULL` без значения по умолчанию добавляется как `NULL` с предупреждением;
  модули переносятся через `CREATE OR ALTER`. Скрипт можно сохранить, открыть в SQL-редакторе (в режиме «только
  чтение») или выполнить — только после ввода имени целевой базы, **одной транзакцией**: при ошибке откатывается всё.
  Значения в скрипте данных экранируются (`N'O''Brien'`, ISO-даты, `0x…`).
* **Документация базы** в Word, PDF, HTML и Markdown: обзор, **схема связей** (рисунок; для больших баз — наиболее
  связанные таблицы и полный список связей таблицей), таблицы со столбцами, ключами, индексами, входящими ссылками и
  триггерами, представления, процедуры и функции с параметрами и текстом, описания `MS_Description`. При повторном
  формировании добавляется раздел **«Изменения с прошлой версии документации»** (снимки структуры хранятся в папке
  данных программы). Недоступные из-за прав сведения перечисляются в документе.

**Ограничения этапа 6.** Сравнение данных читает обе таблицы в память (лимит по умолчанию 200 000 строк, настраивается).
Не сравниваются: права, пользователи и роли, синонимы, последовательности, табличные типы, секционирование, полнотекстовые
и XML-индексы (последние в скрипте помечаются «вручную»). Изменение первичного ключа, IDENTITY и вычисляемых столбцов
скрипт не выполняет — помечает для ручной работы. `CREATE OR ALTER` требует SQL Server 2016 SP1+. Схема связей
автоматическая и для очень связанных баз может быть плотной — точные связи всегда есть в таблице.

### Завершение (этап 7)

* **Справка** в программе (F1): руководства пользователя и администратора, «Что нового», «О программе» с проверкой
  окружения и **диагностическим архивом** (пароли замаскированы, список подключений не выгружается).
* **Резервная копия настроек**: экспорт и импорт подключений (без паролей), шаблонов, избранного, SQL-сценариев и
  задач, выборочно и с режимом «заменять / не заменять». При импорте задачи приходят выключенными, подтверждения
  сценариев снимаются. «Сбросить настройки» — к значениям по умолчанию.
* **Защита от двойного выполнения**: одна копия окна на пользователя; одна и та же задача не выполняется одновременно
  в окне и в Планировщике Windows (межпроцессная блокировка, которую ОС снимает при аварийном завершении).
* **Уведомления в области уведомлений Windows**, **сочетания клавиш** (Ctrl+1…9, F1, Ctrl+Shift+N), значок программы.
* **Сборка .exe** через PyInstaller: `packaging\build.ps1` (прогон тестов → значок → ресурс версии → сборка → ZIP).

## Батники (Windows)

Для всех действий есть готовые `.bat`-файлы. Проще всего запустить **`menu.bat`** в корне проекта — откроется меню
со всеми пунктами. Отдельные файлы лежат в папке `bat\` (их можно запускать двойным щелчком):

| Файл | Что делает |
| --- | --- |
| `menu.bat` | Меню со всеми пунктами ниже |
| `bat\install.bat` | Находит Python 3.11+, создаёт `.venv`, ставит библиотеки, проверяет окружение (повторный запуск — обновление) |
| `bat\run.bat` | Запускает программу без консоли |
| `bat\run_console.bat` | Запускает с консолью — если программа не открывается, здесь видна причина |
| `bat\check_env.bat` | Проверка окружения: Python, библиотеки, драйвер ODBC, LibreOffice, папка данных |
| `bat\tests_fast.bat` | Быстрые тесты (около минуты) |
| `bat\tests.bat` | Все тесты (с LibreOffice — несколько минут) |
| `bat\tests_integration.bat` | Тесты с реальным SQL Server: спрашивает сервер, базу, способ входа; пароль вводится скрыто |
| `bat\build_exe.bat` | Сборка `.exe` (тесты → значок → версия → PyInstaller → ZIP), открывает папку `dist` |
| `bat\list_tasks.bat` | Список задач автоматизации |
| `bat\run_task.bat` | Выполнить задачу: по аргументу `run_task.bat ID` или выбрать из списка |
| `bat\export_settings.bat` | Экспорт настроек (без паролей) в «Документы\DB Workspace Pro\Настройки» |
| `bat\import_settings.bat` | Импорт настроек: перетащите файл .zip на батник (окно программы должно быть закрыто) |
| `bat\diagnostics.bat` | Диагностический архив на Рабочий стол |
| `bat\open_data.bat` | Открывает папку данных и журналов |
| `bat\clean.bat` | Удаляет временные файлы сборки (`__pycache__`, `build`, `dist`); данные программы не трогает |

Тесты запускаются со «сторожем»: если тест зависает дольше 10 минут (`DBWP_TEST_TIMEOUT`), прогон прерывается, а в
консоль и отчёт записывается место зависания. Если что-то не прошло — пришлите файл отчёта.

Первый запуск: `menu.bat` → `1` (установка) → `2` (запуск). Батники рассчитаны на Windows 10/11 (файлы в UTF-8,
переключение консоли в UTF-8 выполняется автоматически).

Те же действия доступны из командной строки: `python main.py --list-tasks | --run-task ID | --export-config ПУТЬ |
--import-config ФАЙЛ [--no-overwrite] [--sections …] | --diagnostics ПУТЬ | --paths`. Коды выхода: 0 — успешно,
1 — с замечаниями, 2 — ошибка, 3 — импорт невозможен, пока открыто окно программы.

## Установка (Windows)

1. Python 3.11 (подойдёт 3.10+).
2. **Microsoft ODBC Driver 18 for SQL Server** — https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server
   (для PDF дополнительно **LibreOffice** — https://www.libreoffice.org/download/ ; без него остальные форматы работают)
3. Зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts/check_env.py     # проверка окружения
```

## Запуск

```powershell
python main.py                      # программа
python main.py --list-tasks         # задачи автоматизации (без окна)
python main.py --run-task <ID>      # выполнить задачу без окна (так её запускает Планировщик Windows)
```

Данные приложения: `%APPDATA%\DBWorkspacePro` (переопределяется переменной `DBWP_HOME`).

## Тесты

```powershell
pip install -r requirements-dev.txt
python -m pytest                      # или: python -m unittest discover -s tests -t .
```

Тесты используют имитацию ODBC-сервера (`tests/fakes.py`) и не требуют SQL Server. Дымовой тест интерфейса
(`tests/test_ui_smoke.py`) при установленном PySide6 запускает окно в режиме `offscreen`.

**Интеграционные тесты с реальным сервером** (только чтение, выключены по умолчанию) — см. docstring в
`tests/integration/test_real_server.py`: задайте `DBWP_TEST_SERVER` и учётные данные тестового сервера
через переменные окружения.

## Сборка .exe

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Результат: `dist\DBWorkspacePro\DBWorkspacePro.exe` и архив `dist\DBWorkspacePro-<версия>-win64.zip`. Сборка
останавливается, если не проходят тесты. Подробности — в руководстве администратора.

## Что проверено и что нет

Проверено автоматическими тестами в среде разработки (Linux, Python 3.12): ядро всех модулей, генерация отчётов и
документации (с настоящим LibreOffice и проверкой PDF), 100 маршрутов конвертера на настоящих файлах, планировщик,
резервное копирование и сравнение — на имитации SQL Server; интерфейс — дымовыми тестами с заглушкой Qt.

**Не проверено** (в среде разработки нет этих компонентов): работа с реальным SQL Server (есть интеграционные тесты
по переменным `DBWP_TEST_*`), интерфейс на настоящем PySide6, функции Windows (хранилище паролей, Планировщик
Windows, `taskkill`), открытие результатов в Microsoft Word/Excel, сборка PyInstaller. Перед использованием в работе
выполните интеграционные тесты на тестовом сервере и проверьте интерфейс.

## Безопасность (кратко)

* Пароли — только в системном хранилище; в журналах маскируются.
* Имена баз/объектов вставляются в SQL только через `quote_ident`, значения — параметрами `?`.
* Значения в строке подключения экранируются (`{…}`, `}}`), пароль не логируется.
* Изменяющие команды никогда не повторяются автоматически; повтор после потери связи — только для чтения и
  только если потребителю ещё не передано ни одной порции данных.

## Известные ограничения (сводно)

* Проверки на реальных SQL Server, PySide6 и Windows не выполнялись — см. «Что проверено и что нет».
* Сравнение данных и большие JSON читаются в память (лимиты настраиваются, превышение — понятная ошибка).
* Встроенные преобразования Markdown/HTML/DOCX сохраняют структуру, но не изображения и сложное оформление.
* Оглавление Word получает номера страниц после «Обновить поле»; вид PDF зависит от шрифтов LibreOffice.
* Встроенный планировщик работает, пока открыта программа (для остального — задания Планировщика Windows).
* Не сравниваются права, роли, синонимы, последовательности, табличные типы, секционирование.
* Уведомления только в программе и в области уведомлений Windows (электронная почта не отправляется).
