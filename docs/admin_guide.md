# Руководство администратора DB Workspace Pro

## Требования

* Windows 10/11 (64-бит). Исходный код также запускается на Linux для разработки и тестов.
* Microsoft ODBC Driver 18 (или 17) for SQL Server.
* SQL Server 2012 или новее; для `CREATE OR ALTER` в скриптах синхронизации — 2016 SP1 или новее.
* Для PDF и форматов DOC/ODT/RTF/XLS — LibreOffice (необязательно).
* Для запуска из исходников — Python 3.11+ и пакеты из `requirements.txt`.

## Установка

**Из сборки:** распакуйте архив `DBWorkspacePro-<версия>-win64.zip` в любую папку и запустите `DBWorkspacePro.exe`.
Права администратора не нужны.

**Из исходников (проще всего):** запустите `menu.bat` в корне проекта и выберите `1` (установка), затем `2`
(запуск). Для каждого действия есть отдельный файл в папке `bat\` — список в README.

**Из исходников вручную:**

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python scripts\check_env.py
.venv\Scripts\python main.py
```

## LibreOffice

Порядок поиска: путь из настроек (файл `soffice.exe`, папка `program` или основная папка установки; если путь не
подходит — поиск продолжается автоматически), PATH, реестр Windows (`App Paths\soffice.exe`,
`LibreOffice\UNO\InstallPath`, `LibreOffice\LibreOffice\<версия>\Path`), `%ProgramFiles%`, `%ProgramFiles(x86)%`,
`%LOCALAPPDATA%\Programs` (папки `LibreOffice*`), Scoop, PortableApps. Диагностика: `main.py --find-libreoffice`
или `bat\find_libreoffice.bat` — показывает найденный путь и все проверенные места.

## Где хранятся данные

| Что | Где |
| --- | --- |
| Настройки, подключения, история, задачи | `%APPDATA%\DBWorkspacePro\data\app.sqlite3` (SQLite) |
| Журналы | `%APPDATA%\DBWorkspacePro\logs` |
| Пользовательские шаблоны отчётов | `%APPDATA%\DBWorkspacePro\data\templates` |
| Снимки структуры и данных (для сравнения) | `%APPDATA%\DBWorkspacePro\data\schema_snapshots`, `...\snapshots` |
| Пароли | Диспетчер учётных данных Windows (Credential Manager) |

Папку можно переопределить переменной окружения `DBWP_HOME`. Запускается одна копия программы на пользователя.

## Права SQL Server по функциям

| Функция | Нужные права |
| --- | --- |
| Просмотр объектов, отчёты, экспорт, документация | Доступ к базе (например, `db_datareader`) и VIEW DEFINITION для текстов модулей |
| Сравнение структуры | То же, на обеих базах |
| Изменения из SQL-редактора и сценариев | Соответствующие права на запись или изменение схемы |
| Резервное копирование | `db_backupoperator` в базе; служба SQL Server должна иметь право записи в папку на сервере |
| Проверка копии (RESTORE VERIFYONLY), восстановление в новую базу | CREATE DATABASE (или `dbcreator`) |
| История копий | Чтение `msdb.dbo.backupset` |
| Размеры всех баз | VIEW ANY DEFINITION; иначе показывается размер выбранной базы |
| Активные запросы и блокировки | VIEW SERVER STATE; без него раздел не показывается |

Рекомендуется работать под учётной записью с минимально необходимыми правами, особенно для задач по расписанию.

## Безопасность

* Пароли хранятся только в системном хранилище учётных данных; в журналах значения вида `PWD=...` маскируются.
* Значения в запросах передаются параметрами, имена объектов экранируются.
* SQL-редактор по умолчанию работает «только на чтение»; блокировка действует в ядре, а не только в интерфейсе.
* Изменяющие SQL-сценарии требуют разрешения и подтверждения точного текста (по хешу).
* Скрипты синхронизации выполняются только после ввода имени целевой базы, одной транзакцией.
* Резервные копии программы удаляются только по явной настройке с согласием и только файлы с именами программы.
* При импорте настроек задачи выключаются, подтверждения сценариев снимаются, пароли не переносятся.
* Программа не отправляет данные во внешние сервисы.

## Задания Планировщика Windows

Кнопка «Планировщик Windows…» формирует XML-описание задания и команду `schtasks`. Задание выполняется от имени
пользователя, когда он вошёл в систему (так доступны сохранённые пароли). Задача запускается командой
`DBWorkspacePro.exe --run-task <ID>` (из исходников: `python main.py --run-task <ID>`); код выхода: 0 — успешно,
1 — с замечаниями, 2 — ошибка. Вывод сборки без консоли пишется в `logs\cli-output.txt`. Список задач:
`--list-tasks`.

## Командная строка и батники

| Команда | Батник | Назначение |
| --- | --- | --- |
| `main.py --list-tasks` | `bat\list_tasks.bat` | Список задач |
| `main.py --run-task ID` | `bat\run_task.bat` | Выполнить задачу |
| `main.py --export-config ПУТЬ` | `bat\export_settings.bat` | Экспорт настроек без паролей |
| `main.py --import-config ФАЙЛ` | `bat\import_settings.bat` | Импорт настроек (окно должно быть закрыто) |
| `main.py --diagnostics ПУТЬ` | `bat\diagnostics.bat` | Диагностический архив |
| `main.py --paths` | `bat\open_data.bat` | Папки данных и журналов |

Коды выхода: 0 — успешно, 1 — с замечаниями, 2 — ошибка, 3 — импорт невозможен, пока открыто окно программы.

## Резервная копия настроек и перенос на другой компьютер

«Настройки» → «Экспорт настроек» создаёт ZIP с подключениями (без паролей), шаблонами, избранными запросами,
SQL-сценариями и задачами. На другом компьютере — «Импорт настроек». После импорта: введите пароли подключений,
проверьте и подтвердите изменяющие сценарии, проверьте и включите задачи.

## Диагностика

«Справка» → «О программе» → «Собрать диагностический архив»: проверка окружения, версии, настройки, последние
ошибки и журналы. Пароли маскируются; список подключений и история запросов не включаются. Журналы и тексты ошибок
могут содержать имена серверов и баз данных — просмотрите архив перед отправкой за пределы организации.

## Сборка .exe

На Windows, из корня проекта:

```
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Скрипт создаёт отдельное окружение, прогоняет тесты (сборка останавливается при ошибке), рисует значок, формирует
ресурс версии и собирает `dist\DBWorkspacePro\DBWorkspacePro.exe` (PyInstaller, режим «папкой»), затем упаковывает
архив. Спецификация: `packaging\DBWorkspacePro.spec`.

## Тесты

```
python -m unittest discover -s tests -t .
```

Медленную полную проверку всех маршрутов конвертера можно отключить: `DBWP_SKIP_SLOW=1`. Интеграционные тесты с
реальным сервером включаются переменными: `DBWP_TEST_SERVER`, `DBWP_TEST_DATABASE`, для входа SQL Server —
`DBWP_TEST_AUTH=sql`, `DBWP_TEST_USER`, `DBWP_TEST_PASSWORD` (и `DBWP_TEST_TRUST_CERT=1` для самоподписанного сертификата). Тест резервного копирования дополнительно требует `DBWP_TEST_BACKUP_FOLDER`
(папка на сервере). Все интеграционные тесты, кроме резервного копирования, только читают данные.

## Обновление

Замените папку программы новой сборкой. Данные в `%APPDATA%\DBWorkspacePro` сохраняются; структура базы настроек
обновляется автоматически при первом запуске. Перед обновлением рекомендуется сделать «Экспорт настроек».
